# Hero Limit для HotA

[English](README.en.md)

## Назначение

Мод меняет правила найма в одиночной игре Heroes III: Horn of the Abyss 1.8.1. У человека и компьютера по одному герою на старте. По умолчанию каждый может нанять в таверне ещё двух за всю партию. Перед игрой этот лимит можно уменьшить до одного дополнительного найма или до нуля.

**Сохранения в v0.1.0.** Мод хранит остаток наймов в памяти. После загрузки сохранения он принимает текущий состав героев за стартовый. Чтобы лимит действовал всю партию, начните новую игру и сыграйте её за один сеанс.

## Установка

Для установки нужна HotA 1.8.1 с HD Mod. Оба архива доступны на странице [тестового выпуска v0.1.0](https://github.com/metalebedenko/hota-hero-limit/releases/tag/v0.1.0).

- **HeroLimit-HotA-1.8.1.zip**. Распакуйте архив, запустите `HeroLimitSetup.exe` и выберите `h3hota HD.exe` из установленной игры. Затем запускайте `h3hota HeroLimit.exe`.
- **HeroLimit-HotA-1.8.1-manual.zip**. Скопируйте DLL и INI рядом с игрой и создайте отдельный EXE скриптом из архива. Команды для Windows и Mac есть в [MANUAL.txt](MANUAL.txt).

Установщик проверяет совместимость движка, а мод при запуске — игровых функций. В CrossOver откройте установщик и игру в той же бутылке, где установлена HotA. Для игры с исходными правилами используйте обычный `h3hota HD.exe`. Подробности в [INSTALL.txt](INSTALL.txt).

## Правила найма

Перед началом партии можно изменить [HeroLimit.ini](HeroLimit.ini). По умолчанию установлены `HeroesPerGame=3`, `RetreatIsPermanent=false` и `PrisonsEnabled=true`.

| Параметр `[Rules]` | Значения |
| --- | --- |
| `HeroesPerGame` | `1`, `2`, `3`, включая стартового героя |
| `RetreatIsPermanent` | `true` блокирует возврат сбежавшего героя, `false` разрешает выкуп прежним владельцем без расхода найма |
| `PrisonsEnabled` | `true` разрешает освобождение героя без расхода найма, `false` закрывает этот способ получения героя |

По умолчанию прежний владелец может выкупить того же героя после побега или капитуляции, даже если все наймы потрачены. Освобождение пленника тоже не расходует найм. Гибель или увольнение героя не пополняет запас. Если погибший снова появится в обычной таверне, для его покупки понадобится один из оставшихся наймов.

## Работа с проектом

`sh build.sh` проверяет логику на macOS и собирает в `dist/` два ZIP-архива и диагностические Win32-артефакты. Сборка использует LLVM-MinGW внутри `.sandbox/toolchain/`. Путь к компилятору можно задать через `WINDOWS_CXX`, путь к компилятору ресурсов через `WINDOWS_WINDRES`. Архивы содержат файлы мода, установщик и инструкции.

Внутренняя модель умеет делать снимок правил и оставшихся наймов. В v0.1.0 этот снимок хранится отдельно от игрового сохранения.

В диагностической сборке `HeroLimitProbe.exe` загружает DLL и проверяет правила из указанного INI. Диагностическую DLL пока не требуется копировать в установленную HotA.

```powershell
.\HeroLimitProbe.exe .\HeroLimit.Probe.dll .\HeroLimit.ini
```

## Игровая проверка

В одиночной партии с HD Mod 5.8 R31 в CrossOver подтвердили, что лимит срабатывает у человека и компьютера. Прежний владелец смог выкупить сбежавшего героя даже после того, как исчерпал наймы. Для капитуляции и тюрем прошли проверки правил и загрузки DLL. Эти два сценария ещё предстоит проверить в самой игре. Сетевой режим не проверяли.

`sh build.sh` также собирает `.sandbox/build/HeroLim.dll`. Команда `python3 prepare_lab.py` проверяет версии файлов и создаёт отдельную копию игры в `.sandbox/game-cx-limit`. В эту копию добавляются DLL и `HeroLimit.ini`, а исполняемый файл получает импорт DLL. Готовые партии не копируются.

Для проверки начните новую одиночную партию с ИИ и без ограничения найма в шаблоне. Строка `active heroes=3` в `HeroLimit.log` означает, что проверки встроились в функции HotA. Журнал показывает успешные покупки, отказы, исходы боя и освобождения пленников с остатком наймов по цветам.
