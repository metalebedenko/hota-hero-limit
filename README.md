# Hero Limit для HotA

## Назначение

Опциональный офлайн-режим Heroes III: Horn of the Abyss. Каждый цвет начинает с одним героем и получает от нуля до двух дополнительных наймов на партию. Человек и ИИ подчиняются одним правилам.

## Установка

Скачайте один из архивов в разделе [Releases](https://github.com/metalebedenko/hota-hero-limit/releases).

- **HeroLimit-HotA-1.8.1.zip**. Распакуйте архив, запустите `HeroLimitSetup.exe` и выберите `h3hota HD.exe` из установленной игры. Затем запускайте `h3hota HeroLimit.exe`.
- **HeroLimit-HotA-1.8.1-manual.zip**. Скопируйте DLL и INI рядом с игрой и создайте отдельный EXE скриптом из архива. Команды для Windows и Mac есть в [MANUAL.txt](MANUAL.txt).

Установщик сверяет код HotA 1.8.1. DLL проверяет формы игровых функций при запуске. Из выпусков HD Mod игровой прогон прошёл на 5.8 R31. Для запуска через CrossOver используйте бутылку, в которой установлена игра. Подробности в [INSTALL.txt](INSTALL.txt).

## Работа с проектом

`sh build.sh` проверяет логику на macOS и собирает в `dist/` два ZIP-архива и диагностические Win32-артефакты. Сборка использует LLVM-MinGW внутри `.sandbox/toolchain/`. Путь к компилятору можно задать через `WINDOWS_CXX`, путь к компилятору ресурсов через `WINDOWS_WINDRES`. Архивы содержат файлы мода, установщик и инструкции.

В диагностической сборке `HeroLimitProbe.exe` загружает DLL и проверяет правила из указанного INI. Диагностическую DLL пока не требуется копировать в установленную HotA.

```powershell
.\HeroLimitProbe.exe .\HeroLimit.Probe.dll .\HeroLimit.ini
```

| Параметр `[Rules]` | Значения |
| --- | --- |
| `HeroesPerGame` | `1`, `2`, `3`, включая стартового героя |
| `RetreatIsPermanent` | `true` блокирует возврат сбежавшего героя, `false` разрешает выкуп прежним владельцем без расхода найма |
| `PrisonsEnabled` | `true` разрешает освобождение героя без расхода найма, `false` закрывает этот способ получения героя |

В текущем INI прежний владелец может выкупить того же героя после побега и капитуляции, даже когда наймы закончились. Освобождение пленника сохраняет остаток наймов. Гибель героя сохраняет потраченный слот. Если погибший снова появится в обычной таверне, на его покупку нужен свободный слот. Правила и остатки бюджета входят в снимок состояния модели. Игровые сохранения пока не записывают этот снимок.

## Игровая проверка

`sh build.sh` также собирает `.sandbox/build/HeroLim.dll`. Команда `python3 prepare_lab.py` проверяет версии файлов и создаёт отдельную копию игры в `.sandbox/game-cx-limit`. В эту копию добавляются DLL и `HeroLimit.ini`, а исполняемый файл получает импорт DLL. Готовые партии не копируются.

Для проверки начните новую одиночную партию с ИИ и без ограничения найма в шаблоне. Строка `active heroes=3` в `HeroLimit.log` означает, что проверки встроились в функции HotA. Журнал показывает успешные покупки, отказы, исходы боя и освобождения пленников с остатком наймов по цветам. В игре подтверждены обычный найм у человека и ИИ и выкуп после побега. Для капитуляции и тюрем пройдены проверки модели и загрузки DLL. Игровые сценарии и сетевой режим ещё не проверены.
